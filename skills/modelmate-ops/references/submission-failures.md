# 提交失败：工作区、代码快照与入口验收

用于“提交失败、运行0秒、没有排队时间或运行日志”，以及 Notebook 测试通过却无法创建正式训练的情况。先确认停在哪个阶段，不先换入口、升级框架或调整训练预算。

## 提交前：检查平台真正复制的范围

在一种已核验的 S3 后端部署中，平台从 Notebook 创建训练任务时复制的是**整个 Notebook 代码工作区**，不是启动文件所在的最小目录。相邻旧项目、测试目录也会参与复制。具体复制根通过当前文件面板、平台帮助及实际对象映射确认；不把某个部署的挂载或存储前缀写死成通用值。

该部署内置《调试Notebook》明确禁止在训练工作目录创建或使用文件、目录软链接。操作系统能读取链接目标，不代表平台的文件同步/快照复制能够处理链接。`project_archive.py` 拒绝包内链接，也不能替代检查包外的整个 Notebook 工作区。

- pytest 的 `tmp_path`/临时目录机制可能创建 `*current` 目录链接。测试临时工作目录及 `--basetemp` 放在**整个代码复制根之外**的已确认可写存储中，每次验证使用独立目录。pytest 会清理指定的 basetemp，不能指向已有结果或其他任务目录。
- 发布前用 `lstat` 或不跟随链接的目录枚举检查真实复制范围，包括隐藏目录、旧验证目录和失效链接。限制枚举数量，遇到权限错误或超限要报告“未完成”，不能记为零链接。
- 检查到链接时先记录来源和目标。不要递归删除测试目录、删除链接目标，或把整个环境跟随链接打包进去。其他部署的链接支持以其实际合同为准。

## 零秒失败：沿实际快照收集证据

1. 固定本次作业/批次 ID、提交时间、源 Notebook、所选启动文件和资源。区分“提交失败”“排队”“容器部署失败”“入口退出”。零秒和没有运行日志提示先检查提交链路，不能单独证明根因。
2. 在批次详情查**系统日志**及该版本提供的 `submit.log`，与部署日志、用户运行日志区分。Notebook 的 Jupyter、SSH 日志没有事件，不证明平台未处理提交；日志所在对象路径按实际目录/官方文档确认。
3. 有平台已配置的存储 SDK 和本用户权限时，只读检查**本次作业实际 app 快照**，与 Notebook 源端分开。映射从平台元数据或 SDK 配置取得，不猜租户前缀、不打印存储密钥；存储权限不等于作业管理权限。
4. 核对入口是否存在、字节长度、SHA256，以及必要源码清单是否完整。源端正确而作业端缺失，优先追复制阶段。若使用共享源码 capsule，分别核快照中的 bootstrap 与它声明的共享版本。
5. 若快照只复制了一部分，保存最后已复制对象、源端下一对象及其本地 `lstat/readlink` 类型；比较目录前缀和缺失清单。只有确认当前复制顺序可比较时，才把“最后/下一项”用作边界证据。对象列表须处理分页，并设预算；一页对象数不能当完整数量。
6. 将快照边界、对象类型与当前平台约束联合判断。镜像查询辅助服务异常可以另记，但不能仅凭它改镜像。也不能因换过 Shell/Python 入口仍失败，就认定平台不支持某种扩展名。

缺少启动回执也不单独证明入口未执行：某些 bootstrap 会先做校验再打印，须结合实际快照和系统日志。

## 限定修复与重新验收

确认是自己验证产生的链接后，先排除相关活动测试/写进程；在代码复制根之外保存准确路径、链接目标和元数据，以**不跟随链接**的归档保存链接本体。只 `unlink` 已登记且身份未变的链接节点，保留所有普通文件、链接目标、训练 claim 和有效结果。未知归属或仍被使用的链接不要批量清理。

修复后再次不跟随链接检查整个复制根；比对普通文件、冻结源码和入口摘要。存在对象存储同步时，还需有界核对源端同名链接对象确已消失、普通对象仍在，不能仅以本地删除成功作为提交条件。不要直接修改旧失败作业的快照。

从修正后的 Notebook **新建作业**；不要假定对旧作业点重试会重新取源码。记录新 ID，再核新快照、容器启动、实际 Python、分配的设备及首个计算阶段。链接修复没有改变源码时，不必为此改训练参数或重传同一代码包。是否还需重新同步以当前平台为准。

若再次失败，先验证新快照是否完整，再沿该次系统日志继续定位，不重复清理或无边界重提。部署修复、正式作业启动、训练完成是不同的验收结果。

## 已核验案例与结论边界

2026-10-31 的一次匿名实践中，两次提交均为0秒失败；实际作业快照分别只含255和283个对象。两次复制边界之后的精确下一源对象，都是 pytest 创建的 `*current` 目录软链接。第二次所选 Python 入口存在于源端，却未进入作业快照；第一次的 Shell 入口已复制，但整体快照仍未完成。

工作区共发现60个自有测试链接。备份并只移除链接后，620个普通测试文件和117份冻结源码逐一核验未变；云端源对象也核验了链接消失、普通文件及入口保留。结合平台内置软链接禁令，这些证据支持“工作区链接阻断快照复制”。未取得控制面的原始异常堆栈；该次修复记录也未包含后续新作业成功启动的证据，不将修复验收写成正式训练成功。

此处只保留可复用的证据结构。真实作业 ID、内网地址、租户路径、连接 profile 和取证包保存在项目私有工作区。来源与验证范围见 [sources.md](sources.md)。
