# 非 SSH 路线：用网页完成部署与运行

适用：没有 SSH 开关、暂时无法直连，或用户希望只使用浏览器。使用 Notebook 的 JupyterLab 文件面板和 Terminal，仍能完成代码准备、修改、测试、平台提交与结果回收。无需为了走完流程先安装 SSH。

共用的资产、配置、作业表单和验收规则见 [workflow.md](workflow.md)。连接条件改变后，可转到 [ssh.md](ssh.md)，继续使用同一份源码与运行身份。

## 1. 登录并确认工作空间

使用机构提供的 ModelMate 入口，按现有账号或统一认证流程登录。确认当前租户、项目或课题；同名目录不代表同一工作空间。

Codex 有可用浏览器控制时，直接依据当前页面协助；没有时，让用户提供本步所需的页面信息，并给出准确的点击路径。不要把所有后续命令都交给用户自行猜测。

先确认本次目标：新运行、修复后重提、恢复指定运行、仅评测，还是下载结果。已有配置和会话能够确定的信息直接复用。

## 2. 创建或复用 Notebook

常见入口为“模型训练 → 模型开发”或“Notebook”，具体名称按当前界面。

1. 查看已有实例，优先复用适合本项目且可访问的 Notebook。
2. 需要新建时，填写英文名称，选择与项目框架、架构兼容的镜像、资源池和开发规格。
3. 启动目录从平台文件选择器选取。某些部署要求租户代码桶内的特定子目录，按该部署帮助创建。
4. 设置合适的自动关闭时间。只准备代码时无需默认选择正式训练的多卡规格。
5. 创建后启动，等待实例就绪，进入 JupyterLab。

资源池不可选、没有配额或租户无权限时，先核对所属工作空间和资源授权。镜像名称、可用规格和 Notebook 生命周期不在各部署间固定。

## 3. 打开正确的终端

在 JupyterLab 的 Launcher 或新建菜单中选择 **Terminal**。这是远端 Linux Shell，不是本地 PowerShell，也不是 Notebook 代码单元。

以下命令在 **Notebook Terminal** 执行，普通 **Enter** 运行：

```bash
pwd -P
whoami
hostname
command -v python3
```

记录目录和主机身份。确认文件面板当前所在目录；必要时从文件面板目标位置打开 Terminal，再运行 `pwd -P`。后续上传目录、项目根和下载目录都从这里确定。

Terminal 中粘贴多行 Bash 后按 Enter；Shift+Enter 用于 Notebook 代码单元。出现 `>` 续行提示时，检查引号或 here-document 是否完整，不随意补命令。

## 4. 上传代码并展开到新目录

先在本地准备完整发布包和 SHA256。包应包含入口、配置、源码及入口确实依赖的文件；大型数据和权重按 [workflow.md](workflow.md) 的存储安排准备。

以下以本地 Windows 为例，在**公开仓库根目录**使用打包工具；自定义 skill 安装目录不影响此路径。若只保留安装后的 skill，由助手从实际安装位置取得脚本绝对路径，不固定猜用户目录：

```powershell
$ArchiveTool = (Resolve-Path 'skills/modelmate-ops/scripts/project_archive.py').Path
$SourceRoot = Read-Host '项目源码目录的完整本地路径'
$CodeZip = Read-Host '新代码 ZIP 的完整输出路径'
python -X utf8 $ArchiveTool pack --source $SourceRoot --output $CodeZip
```

工具拒绝覆盖已有归档，并为代码写入内容清单。核对完整源码依赖和排除项：`models`、`datasets`、`data` 中的 Python 源码会保留，数据文件/权重按扩展名排除；其他生成目录也会报告。确实需要的文件可用显式 file-list，不能把“包生成成功”当成源码闭包已经完整。大型资产按共用流程单独准备，不把凭据放进代码包。

在 JupyterLab 文件面板进入已确认的上传位置，选择上传按钮或拖入文件。上传本次 ZIP，以及 skill 内的 `scripts/project_archive.py`。等待传输完成，确认文件名与大小；不要仅凭浏览器进度条推断已经可运行。

在 **本地 PowerShell** 查看本次包摘要：

```powershell
$PackagePath = Read-Host '代码 ZIP 的完整本地路径'
Get-FileHash -LiteralPath $PackagePath -Algorithm SHA256
```

在 **Notebook Terminal** 输入准确的远端路径，比较摘要：

```bash
read -r -p '已上传代码 ZIP 的绝对路径: ' MM_ARCHIVE
sha256sum -- "$MM_ARCHIVE"
python3 -m zipfile -l "$MM_ARCHIVE"
```

`MM_ARCHIVE` 来自文件面板对应目录和上传后的实际文件名，摘要应与本地一致。使用刚上传的解包工具展开到**新的源码目录**：

```bash
read -r -p '已上传 project_archive.py 的绝对路径: ' MM_ARCHIVE_TOOL
read -r -p '本次新建源码目录的绝对路径: ' MM_RELEASE
python3 "$MM_ARCHIVE_TOOL" unpack --archive "$MM_ARCHIVE" --destination "$MM_RELEASE"
```

`MM_RELEASE` 是当前用户可写位置下尚不存在的新目录。工具验证路径、链接、重名和清单摘要；它只接受本工具 `pack` 生成的代码 ZIP，不能拿任意历史归档强行解包。

不要直接覆盖旧源码。展开后定位入口文件；平台填写的是相对于所选代码目录的路径，不能把 ZIP 文件本身当启动入口。

## 5. 准备数据、模型和实际 Python

依照 [workflow.md](workflow.md) 确认数据来源、持久化挂载、模型路径、输出位置和必要权限。文件放进共享存储与注册成平台数据集是两件事；项目直接读取挂载文件时，可能不必填写平台数据集字段。

电脑上有大数据时，按 [数据上传指南](data-transfer.md) 走平台数据集上传或对象存储客户端，取得真实训练路径后再继续。该指南包含无SSH的首次客户端配置、小文件映射验证和摘要检查；不要求为传大数据临时开SSH。

确认项目所需的运行时或 activation。按项目提供的实际命令激活后，再检查解释器与包来源；Notebook 默认 `python3` 不一定是项目训练环境。

需要检查的最小信息为：

- 实际源码根、启动文件和配置文件；
- 解释器路径、框架与设备依赖版本；
- 数据/模型真实路径和读取权限；
- 新运行的独立输出根与日志根；
- 正常启动所用的默认值与明确覆盖。

使用已有隔离环境，确实缺依赖时再修复对应环境。不要因为一次导入失败就升级整个 Notebook 的框架、驱动或加速库。

## 6. 修改代码与运行检查

JupyterLab 编辑器可直接修改新源码目录中的文件；改前保留版本或备份。对已发布代码，优先使用有版本核对和回执的补丁。

只能粘贴时，由 Codex 提供**完整自含**的 Terminal 命令，包含新增源码，不依赖远端尚不存在的本地脚本。

在本地 PowerShell 复制已生成的粘贴文件：

```powershell
$PastePath = Read-Host '完整粘贴脚本的本地路径'
Get-Content -LiteralPath $PastePath -Raw -Encoding UTF8 | Set-Clipboard
```

然后粘贴到 Notebook Terminal，普通 Enter 执行。优先使用 ASCII 执行封装、UTF-8 源文件和明确的 LF 换行；安装器应在执行业务逻辑前校验 payload。

检查应包括真实解释器下的语法、相关测试、入口参数和源码导入来源。按该入口实际支持的帮助、配置检查或计划功能执行；不是每个训练脚本都支持 `--dry-run` 或 `--show-defaults`。

Notebook 内的 CPU/单卡检查只证明相应环境中的行为，多卡启动与显存由正式分配的资源验收。已提交作业通常使用当时的代码快照，Notebook 后续修改不会自动修复正在运行的作业。

## 7. 在平台页面创建正式作业

准备完成后，按 [workflow.md](workflow.md) 的提交表填写。常见入口是 Notebook 列表中的“创建训练作业”或“训练”。

Codex 应给出本次可见源码目录、相对入口、镜像、Worker/设备规格、数据集与检查点填写方式、运行参数、环境变量和输出路径。正常新交付使用可用默认值；旧项目遗留变量须核对后清理，保留平台设备可见性。

用户已要求运行且目标确定时，完成必要检查后继续提交；无需为每个准备步骤重复询问。点击提交后记录作业/批次 ID。页面超时先查列表，确认是否已经创建，避免重复点击。

## 8. 验收启动与持续观察

先在作业详情查看平台日志：代码取得、入口执行、实际 Python/配置、设备、首个计算阶段。下载代码完成不是训练已经开始。

从日志取得本次运行、输出和日志路径。回到 Notebook Terminal，使用项目对应监控器并固定该目标；若无专用监控器，读取明确日志文件和有限指标，不扫描整个存储。

平台状态、调度领取、实际计算和结果完整性分别确认。ETA 以已测阶段校准；未测最终评估写待校准，不将训练结束时间冒充全流程结束。

停止监控用 Ctrl+C；这通常只停止监控命令。停止正式训练按平台当前作业控制操作，并核对最终状态。

## 9. 打包、网页下载与交接

按 [workflow.md](workflow.md) 导出本次必要结果。使用明确运行目录、文件索引和分析目的；排除权重并不代表其他目录都应该递归打包。

先定位网页文件面板可见的目录，将新归档**复制**过去，保留持久化原件。刷新文件面板，对归档使用下载操作；大包是否适合网页通道按当前部署限制判断。

本地下载后用 `Get-FileHash` 比较远端摘要。只有摘要一致且包内必要记录齐全，才能报告本次结果已完整取回。

交接保留：作业/批次、代码版本、实际配置、运行与日志路径、已执行动作、校验结果及待完成事项。需要恢复时指定确切目标并核对兼容性；不要自动恢复“最新目录”。

常见报错与下一步见 [troubleshooting.md](troubleshooting.md)。
