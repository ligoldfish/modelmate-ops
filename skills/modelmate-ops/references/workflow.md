# 共用流程：数据、代码、训练与结果

无论使用 SSH 还是网页 Terminal，都按下面的实际阶段衔接。助手应先理解已有项目，再完成必要准备；不是每次都重新搭环境或运行示例。

## 1. 确认任务、实例与存储

确认用户要做新训练、修改重提、恢复、只评测还是只下载。先利用工作区 README、入口、配置和现有说明，再询问缺少的关键目标。

区分四个位置：本地电脑负责编辑/传输；Notebook用于准备/调试；正式训练容器使用独立分配的资源；共享存储保存跨容器资产。Notebook 里的 `npu-smi` 或 `ps` 不代表正式作业的设备或进程。

远端先检查：

```bash
whoami
hostname
pwd -P
command -v python3
```

通过平台实例、启动日志和实际目录核对路径。某些部署挂载 DPC，其他部署可能使用对象存储或其他卷；挂载点、写权限和工作区持久性都要现场确认。不能从目录叫 `work` 就推断它是下载根或持久盘。

## 2. 准备数据

已有数据先确认来源、格式、划分和所在位置，避免重复下载。处理或转换后保存 schema、行数、少量样本检查和 SHA/manifest。缺标签、空文件或路径错误不能通过填假数据“修到能跑”。

大型数据与模型放到平台确认的存储，不塞进 Notebook 代码目录。具备本用户权限的 DPC 文件可像普通文件使用；需要对象存储客户端时使用平台实际配置。写入数据文件不等于注册了平台数据集：若任务需要平台数据集 ID、标注或版本管理，另外走对应页面。

从本机上传到存储的页面、SFTP与对象客户端步骤见 [data-transfer.md](data-transfer.md)。先看网页是否支持当前体积，超限时使用该部署批准的客户端；没有SSH也可走这条通道。Endpoint、Bucket、前缀、凭据与挂载映射都说明了取得位置和验收动作。

演示项目可复制 `assets/starter/` 到新目录，执行：

```bash
python3 main.py --prepare-only
```

它生成64条小数据，只用于确认流程。现有研究数据不得用演示数据替代。

运行starter后，`STARTER_RUN=` 给出实际配置、运行ID和输出目录，`METRIC=` 是训练进度，`COMPLETE=` 指向该次 `result.json`。结果目录内有 `result.json`（指标/参数/身份）、`resolved.json`（实际配置）与 `metrics.jsonl`（进度）；它们用于后面的明确文件表，不从目录时间猜“最新一次”。

## 3. 部署与修改

优先传代码包到新目录。使用 `project_archive.py pack` 打包后，SSH 或网页上传包和工具，再用 `unpack` 解到尚不存在的目标目录。它只接受带该工具清单的 ZIP；第三方原始 ZIP 先在本机检查或重新打包，不能凭扩展名直接执行。

默认代码包排除环境/生成输出目录及凭据、权重、常见数据文件扩展名；**不按 `models`、`datasets`、`data` 目录名删除其中的源码**。清单包含打包文件与前100项排除记录，助手应核对入口所需源码/配置闭包。上限为2000文件、单文件32MiB、合计128MiB，目录检查也有条目上限，可对明确用途调整。若使用 `--file-list`，文件表是相对根目录的 JSON 字符串数组，适合精确选择源码或必要的小数据附件。符号链接、越界路径、重复文件与凭据名会被拒绝。

已有代码需修改时，先确认实际源码根和版本。备份目标、记录修改前后摘要、执行语法与有针对性的测试。安装器提示 preimage 不匹配时取真实文件合并，不改预期摘要或强行覆盖。

项目依赖按现有锁文件与兼容矩阵安装到项目自己的运行时。若使用 activation，先检查其来源与内容，再加载。不要因默认 Python 缺包就升级共享 torch/torch_npu 或重建其他项目的环境。

激活后用**实际解释器**检查：

```bash
python3 -c 'import sys; print(sys.executable)'
```

若项目使用专用 Python，以上 `python3` 换成真实解释器；运行真实 `python -m` 入口或项目支持的检查选项，确认模块来自本次源码。activation 可能覆盖 PYTHONPATH，不能只凭激活前的导入结果。

## 4. 准备可运行默认值

由助手把模型/数据、运行时、线程、常规批量、输出和恢复开关写入项目配置或已有默认机制；用户正常使用只需选择源码、入口和资源。路径因租户而异，助手应从已确认挂载和代码中取得，不发明通用的个人目录。

保留平台 NPU mask 等运行环境。高级覆盖可以存在，最终实际值写日志；复制旧表单时清掉旧项目 CONFIG、Python和业务变量覆盖。

检查入口是否接收本部署实际注入参数。实践中即使表单留空，也可能收到 `--checkpoint_url=""`；CONFIG 可能以不同大小写、等号/双 token 和字面引号传来。仅兼容已登记的平台参数，未知业务参数仍报告拼错，不使用 eval。

starter 的本地/Notebook默认配置可直接用。正式作业前，助手把 `config.json` 的 `output_root` 改成已确认可写的持久化**绝对路径**，再打包；不要求用户手填环境变量。检测到正式 `MANAS_JOB_TYPE` 却仍使用相对输出时，starter 会报错。该检查不能替代验证挂载是否持久。

## 5. 测试与提交表

在合适的环境执行语法、导入、配置解析和关键测试；不要默认每个项目都支持 `--check`。需要多卡的探针放在实际分配多卡的环境，Notebook单卡或CPU检查只说明开发环境。

测试临时目录放在平台代码复制根之外，pytest 的 `--basetemp` 使用独立验证目录，避免自动生成的 `*current` 链接进入提交范围。先确认实际复制根：有的部署会复制整个 Notebook 工作区，最小启动目录之外的旧测试目录也会影响提交。对不支持软链接的后端，提交前检查整个复制范围，不能只检查上传包。检查方法、限定修复与验证边界见 [提交与快照排障](submission-failures.md)。

给用户或页面操作工具准备具体表单：

| 字段 | 由助手核实的内容 |
|---|---|
| 源Notebook | 实例名称、实际代码目录及版本 |
| 作业名称 | 唯一名称，符合当前页面规则 |
| 启动文件 | 平台选择器中可见的相对路径，不选ZIP |
| 镜像 | 项目兼容、当前可用的实际配置 |
| 资源池/Worker/规格 | 代码支持与用户预算对应；八卡不自动等于DDP |
| 数据集/检查点 | 确实需要填写的字段；直接读取挂载的项目可能留空 |
| 参数/环境变量 | 正常默认或明确覆盖，清除旧项目遗留 |
| 输出/日志 | 本次持久化根、独立运行身份 |
| 超时/重试 | 与任务相称，避免失败后无边界重跑 |

SSH绝对路径与平台对象存储选择器路径不一定相同。通过 Notebook 文件面板或页面源码树确认映射，不能只给一条 Linux 路径就声称表单已能选择。

## 6. 在页面创建正式训练

已验证部署使用“模型训练/模型开发 → 对应 Notebook → 创建训练作业”。其他版本以实际界面为准。不要因为发现模板Trainer、镜像CLI或存储AK/SK，就自行假定有创建作业API。

有可用浏览器控制时，在当前登录会话和用户授权下协助；没有时把上表的具体值交给用户，只保留这处必要页面节点。提交前确认没有误重复作业；点击超时先看列表，别再次点击试探。

提交后记录平台生成的作业/批次 ID 和创建时间。Notebook也有自己的ID，不能把Notebook的ID当成新建训练作业ID。

若提交即失败、运行0秒且没有用户日志，先查该批次系统日志和实际作业代码快照。需要区分代码复制尚未完成与容器内入口报错；Notebook 里测试通过不能代替快照完整性验收。

## 7. 验收启动、监控和 ETA

按日志区分代码下载、启动入口、激活、实际Python、设备检查与训练阶段。`download complete`不代表训练已开始；首个真实traceback优先于外层NPU错误码。

在平台或本用户存储权限可读时，核本次作业快照中的入口、摘要和必要源码清单，不只检查 Notebook 源端。共享源码 capsule 则同时核快照入口与所声明的共享版本；实际运行日志仍需确认使用了该身份。

固定本次 RUN_ID、OUTPUT_ROOT、LOG_ROOT 和配置/源码身份。SSH可读取共享存储中的本次日志，但不因此拥有训练容器的shell。无SSH时在网页Terminal读同一挂载或平台作业日志。

Notebook改码通常不更新已提交的代码快照；共享运行时、数据和缓存变化仍可能影响旧任务。判断补丁是否生效要看本次执行身份。

队列领取、注册文件、mtime或显存占用不能单独证明计算推进。结合阶段、实际step变化、退出信息与产物完整性解释。并行ETA按最慢任务/关键路径估计，训练后的验证、刷新、最终测评与报告单独计入；未知阶段待校准，不用训练倒计时冒充全流程。

## 8. 失败与恢复

先保留日志和有效产物，定位当次阶段与根因。补源码后通常要从修订后的目录提交新作业；恢复已有运行则需显式目标和兼容身份，不能自动选择最新目录。

关闭监控、断开SSH或关网页都不等于停止训练。清锁或claim前核相关writer和平台状态，不为了“继续跑”默认清理。详见 [故障表](troubleshooting.md)。

## 9. 导出与取回

优先使用项目自己的 exporter/index，保留配置、源码/激活身份、指标、必要raw、阶段日志和成本。没有工具时先制定明确文件清单；不要递归扫描整个存储，也不要因为排除了ckpt就把其他全部打包。

对小型明确结果，保存 JSON 文件表（相对本次运行根）再执行：

例如starter以 `COMPLETE=` 文件的父目录作为运行根，文件表内容为：

```json
["result.json", "resolved.json", "metrics.jsonl"]
```

助手应生成这个JSON文件，再给出实际命令。

```bash
python3 "/absolute/path/to/project_archive.py" export --root "/absolute/run" --file-list "/absolute/analysis-files.json" --output "/absolute/download/analysis.zip"
```

以上均为示意路径，由助手替换成真实的**绝对路径**，特别是前面上传的 `project_archive.py` 位置；不能依赖当前工作目录。新开Terminal后原Shell变量可能已不存在。输出ZIP须在运行根之外。结果列表显式读取、不递归；缺文件或超限会报错，不以“压缩包存在”冒充证据完整。大 gzip 文件按原字节归档，不全量解码占内存；更大raw由项目工具按预算导出，必要时合并小记录。

SSH下载使用源SHA验证；无SSH先把包**复制**到网页文件面板确认可见的目录，下载包与摘要，在本机比对。保留持久化源件。最终交接给出本次身份、完成状态、结果位置、已验证能力和剩余步骤。
